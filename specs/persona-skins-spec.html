Design Spec — Final

Persona Skins

Transform the Style Cart from a utilitarian theme picker into a living skin selector. Three personas — The Designer, The Researcher, The Maker — each with a distinct material object, typographic system, and animation personality. The skin selector itself becomes proof of range. Reviewed by the 0xCreative Committee.

leegordon.design 2026-06-16 Status: Approved — Build

01The Idea

The existing ThemeCart is a dark-mode utility — pick a theme, see tokens. It works, but it speaks to visitors who already know what design systems are. The majority of visitors (clients, collaborators, curious scrollers) see a color picker and move on.

Persona Skins reframe the theme system as a set of three work identities — each one a real mode you operate in. Visitors don't "switch themes." They choose a lens. Each skin changes the portfolio's voice (typography, spacing, accent behavior) and the skin illustration embodies it as a tactile 3D-ish artifact.

The goal is not "cool animations." The goal is: in under 30 seconds, a visitor understands that you think about design in three distinct modes — and can switch between them fluidly.

02The Three Personas

✏

The Designer

Craft · Composition · Polish

The default skin. Bold display type, tight leading, generous whitespace. Accent behaviors: hover reveals, subtle glow on cards, showcase-forward layout where project images lead and process stays behind a fold.

The Researcher

The Maker

Spacier, airier, slightly looser in the joints. Type treatment feels editorial. Accent elements have a glassy, chromatic quality. The portfolio shows work as experiments in progress — prototypes, WIP, conversations — alongside shipped pieces.

Each persona is more than a hue-shift. It changes font stack, spacing rhythm, card density, hero hierarchy, and even the character of the About page bio. A persona is a coherent worldview, not a recolor.

03Persona Portraits — Google Nano Prompts

Each skin is represented by a small illustrated character portrait in the selector panel. Generated with Google Nano (on-device Chrome preview, fast iteration, no credits). The prompts share a unified style — stylized digital illustration, clean linework, bust composition — so all three portraits feel like they belong to the same cast.

Nano Prompt — The Designer
A stylized portrait of a focused creative figure sketching in a notebook, fine pen in hand, head tilted in concentration. Warm rose-pink light catches the hair and shoulder from the top-left. Clean digital illustration with bold linework, matte black background, soft shadow beneath. Bust composition, facing slightly right. 256x256px.
Nano Prompt — The Researcher
A stylized portrait of an inquisitive figure leaning forward, peering through a brass monocle loupe at a small glowing detail. Cool cyan light catches the lens and cheek from the top-left. Clean digital illustration with bold linework, matte black background, soft shadow beneath. Bust composition, facing slightly left. 256x256px.
Nano Prompt — The Maker
A stylized portrait of an energetic builder figure with goggles pushed up on their forehead, holding a small glowing circuit fragment, mid-laugh. Violet-lime light catches the goggles and fingertips from the top-left. Clean digital illustration with bold linework, matte black background, soft shadow beneath. Bust composition, facing forward. 256x256px.

Nano outputs 1024×1024 — downscale & trim to 256×256 PNG with alpha. Expect 5-10 prompt iterations per portrait to get consistent style, expression, and lighting. All three share the same scene setup (matte black, single point-light from top-left, bold linework) so they read as a curated cast of characters.

04Animation Specs

Panel Entrance
The Drawer Slides Into View

The panel slides from the right with a smooth deceleration curve. A subtle scaleX(0.97) adds a slight receding-in perspective without the iOS Safari compositing bugs of rotateY.

initial: { x: "100%", scaleX: 0.97, opacity: 0.85 }
animate:  { x: 0, scaleX: 1, opacity: 1 }
transition: { duration: 0.35, ease: [0.22, 1, 0.36, 1] }
Object Entrance — Per-Skin
Each Object Arrives With Its Own Physics

On panel open, the three skin objects stagger in with distinct arrivals:

  • Designer — Slides from above, slight overshoot settle. Weighty, deliberate.
  • Researcher — Fades in with a precise scale pop (0.85 → 1.0), like a lens snapping into focus.
  • Maker — Floats up from below with a gentle oscillation (yoyo), like a bubble rising.
staggerChildren: 0.08     // each object trails by 80ms
delayChildren:   0.15     // start after panel is ~40% arrived
Hover — Object
Hover Amplifies the Persona (Safari-Safe)

Hovering a skin object triggers a micro-animation reinforcing identity using only GPU-composited properties:

  • Designer — Slight rotation (2°) + warm glow intensify via box-shadow transition.
  • Researcher — A scanning-line sweep across surface via CSS gradient translateX. Settles on focus ring highlight.
  • Maker — Subtle border-glow pulse + slight scale pulse (1.0 → 1.03). No hue-rotate to avoid GPU repaint.
Selection — Theme Switch
Cross-Fade With Staggered Content

When a skin is selected, the portfolio cross-fades over 400ms — text first, then cards, then images. On a static-export Next.js site, this requires client-side state-driven conditional rendering for content variants, or a soft page refresh for full content swaps. CSS/font/spacing changes are client-side instant.

pageTransition: {
  text:  { duration: 0.25, delay: 0 },
  cards: { duration: 0.30, delay: 0.05 },
  images:{ duration: 0.35, delay: 0.10 },
}
// Note: Next.js App Router static export = full page navigations.

06Implementation Roadmap

  • Phase 1 — Skin Illustrations (~1-2 days): Nano prompt iteration, manual cleanup & alpha trim, export 256×256 PNGs.
  • Phase 2 — UI Redesign (~1 day): Rebuild ThemeCart.tsx. Objects-first layout, collapsible token inspector.
  • Phase 3 — Animation Pass (~2 days): Implement entrance, hover, and selection animations. Safari/iOS fallbacks for compositing-safe transforms only.
  • Phase 4 — Persona Content Variants (~2-3 days): Wire three content presets into lib/themes.ts. Scope: About page bio variant + optional Project Process section. Full-site content rewrite deferred.
  • Phase 5 — QA & Polish (~1-2 days): Mobile bottom-sheet on <640px, reduce-motion support, Safari/Edge, static export verification.

Total estimate: 1.5–2 weeks of focused build time. Not 4 days.

07Content Scope

The committee flagged that full-site copy variants per persona would be a content strategy problem masquerading as a config flag. Approved scope:

  • About page: Three 2-sentence bio variants. Designer = craft focus. Researcher = process focus. Maker = build focus.
  • Project pages: Optional Process section surfaced in Researcher mode. If a project has no process content, the section doesn't appear. Never fabricate research artifacts.
  • Hero copy: One headline variant per persona, max 12 words.
  • Everything else: Stays shared. No AI-generated copy anywhere visible.

08Committee Debate

The spec was reviewed by three committee members from the 0xCreative Design Committee. Each member read the full draft, provided a critique, answered the open questions, and voted FOR, AGAINST, or MIXED.

Mia — Creative Strategist
Vote: MIXED

"Animation thinking is sharp, visual concept is right, but three-persona framing flattens Lee's existing 7-theme vocabulary. 'Vibecoder' is brand poison. Never ship placeholder research. Build the interaction shell but reframe personas as view modes that sit on top of the existing theme system, not replacements for it."

Dieter — Systems Architect
Vote: MIXED

"4-day estimate is misleading. rotateY causes iOS Safari compositing bugs. hue-rotate repaints GPU. Tailwind spacing isn't runtime-variable without a rebuild. Static-export Next.js means content variants need client-state wrapping, not a config flag. Ship the skin selector + CSS-driven themes as a polished evolution. Defer content variants to Phase 2."

Carl — Brand Voice
Vote: MIXED

"Designer and Researcher are excellent. Vibecoder is a dated meme wrapped in adjectives. 'Ship · Feel · Agent-Assisted' is credibility poison. Rename to The Maker, change panel title to 'Choose a Lens,' and keep all copy human-written. Ship with two personas if Maker isn't rewriting-ready."

✓ Points of Convergence

  • Build the skin selector. All three agree the interaction shell and object concept should ship.
  • Rename the third persona. Consensus: Vibecoder → The Maker (or The Builder). Tagline: grounded verbs only.
  • Panel header: "Choose a Lens" over "Pick a Persona" — more professional, less cosplay.
  • Asset format: Static PNG with alpha, not Lottie/SVG. CSS micro-animations on top.
  • Persist selection to localStorage. Default to Designer for new visitors.
  • Never fabricate research artifacts. Surfaces real process content only.
  • No AI-generated copy anywhere visible on the portfolio.
  • Animation: Safari-safe. No rotateY, no hue-rotate. Scale, opacity, translate only.
  • Timeline is ~1.5–2 weeks, not 4 days. Content variants are a Phase 2 consideration.
  • Object prompts should share unified lighting (matte black surface, single accent point-light).
Full Committee Writeups

Mia's full critique (Creative Strategist)

"The spec has genuine interaction craft buried under a strategic misstep. The animation thinking is sharp. The visual concept of tactile skin-objects is right. But the core 'three personas' framing flattens Lee's existing design vocabulary into generic LinkedIn job titles — and one of them is actively cringe.

Keep the existing 7 themes as the aesthetic layer. The skin selector should be a compositor: pick a base theme (Void Rose, Cinnabar, Abyssal, Konshu) AND pick a view mode. This preserves the typographic specificity Lee already built while adding the layout-density dimension the personas want.

Unify the object art style. The current prompts describe three different lighting rigs. Revise so all three objects share a consistent language — all are precision metal instruments resting on matte black, lit by a single accent-colored point source.

Scope content variants to one page and one optional tab. Instead of rewriting the entire site's copy per persona, limit to: (a) About page gets a 2-sentence bio variant, and (b) project pages get an optional Process tab that Researcher mode surfaces. This turns a weeks-long content problem into a real, shippable feature. The spec's 2-day estimate for persona content variants is fantasy if it means full-site rewrites."

Dieter's full critique (Systems Architect)

/costs/1: The Tailwind spacing tax. Tailwind utilities are compile-time static. You cannot CSS-variable them at runtime without abandoning the Tailwind design token system. Options: CSS variable approach (destroys Tailwind), component duplication (maintainability nightmare), or runtime class mapping (feasible but touches ~20 components). This is buried in the spec as 'Phase 4 — wire three content presets.' Not a preset problem. A layout system problem. Add 2-3 days.

/costs/2: The Server Component boundary problem. The site uses App Router with static export. Many pages are Server Components that read MDX/JSON at build time. A persona switch is client-side state. Server Components can't re-render based on client state. The Researcher persona showing process artifacts before polished outcome on project pages would require all three variants to be generated at build time, with client-side conditional rendering — tripling build output. Not a 'Phase 4' subtask. A fundamental architecture decision.

/costs/3: Safari compositing bugs. rotateY on a fixed drawer is an iOS Safari rendering bug. hue-rotate oscillation is a full CPU repaint. backdrop-blur on slide-overs frame drops on iPhone 12 and below. Either cut rotateY/hue-rotate or add 1-2 days of mobile-specific fallback engineering.

Nano is not an asset pipeline. Nano produces 1024x1024, not 256x256. Consistency across 3 prompts is speculative — expect 5-10 iterations per object. 'Transparent background feel' will produce gray voids, not alpha. Plan on manual PNG cleanup regardless.

Recommendation: Ship the skin selector + CSS-driven persona themes as a polished evolution of the current ThemeCart. Defer content variants and page transition animations to a post-launch Phase 2. The 80% version is achievable and impressive; the specced 100% version is a rewrite disguised as a feature."

Carl's full critique (Brand Voice)

"The spec is two-thirds excellent and one-third costume. Designer and Researcher are grounded, believable personas with clear typographic logic and real work modes. 'Vibecoder' is a trend-chasing label wrapped in aesthetic adjectives that don't describe a design philosophy — they describe a Pinterest board.

The tag 'Ship · Feel · Agent-Assisted' is credibility poison. 'Feel' is not a design principle. 'Agent-Assisted' sounds like SaaS marketing. In a portfolio, it reads as 'AI wrote this.' It undermines authorship.

Proposed copy changes: (1) Rename Vibecoder → The Maker, rewrite description around discipline (ship/iterate/build), not vibes. (2) Change panel header from 'Pick a Persona' to 'Choose a Lens.' (3) Remove 'Agent-Assisted' from all taglines; replace with grounded verbs.

Never fabricate research artifacts. Use real process content only, or don't show it. Fake research is worse than no research."

09Decisions Made

  • Persona 3 name: The Maker. Alternative considered: Vibecoder (rejected by committee).
  • Panel title: "Choose a Lens."
  • Tagline (Maker): "Build · Iterate · Ship."
  • Asset format: Static PNG 256×256 with alpha. CSS-driven hover animations. No Lottie/SVG war.
  • Persist selection: Yes, via localStorage. Default to Designer on first visit.
  • Research artifacts: Real only. Optional Process section on project pages. No placeholders.
  • AI copy: None anywhere visible. Human-written only.
  • Animation limit: GPU-composited properties only (scale, opacity, translate). No rotateY, no hue-rotate.
  • Timeline: 1.5–2 weeks for Phase 1. Content variants deferred to Phase 2.
  • Object lighting: Unified: matte black surface, single accent-colored point-light from top-left.
